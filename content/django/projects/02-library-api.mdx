
## The brief (PRD)

**Problem.** A small library tracks books and loans on paper; members can't see what's available.

**Users.** Members (borrow and return books, see their own loans) and librarians (staff: manage the
catalogue).

**User stories.**

- Anyone can list and search books, filter by author or year, and sort by title or year.
- Each book shows how many copies are available right now.
- Staff can add, edit and remove books and authors.
- A logged-in member can borrow an available book and return it.
- Members see only their own loans.

**Acceptance criteria.**

- Lists are paginated (10 per page) and the book list costs a fixed number of queries.
- ISBNs are 13 digits; years can't be in the future; errors name the field.
- A member can't borrow a book with no copies left, or the same book twice; two simultaneous borrows
  of the last copy can't both succeed.
- Returning twice is refused with 409.
- OpenAPI schema at `/api/schema/`, Swagger UI at `/api/docs/`.

## Design

| Model    | Fields                                                                             | Notes                                 |
| -------- | ---------------------------------------------------------------------------------- | ------------------------------------- |
| `Author` | `name` (unique)                                                                    |                                       |
| `Book`   | `title`, `isbn` (unique), `author` → Author (PROTECT), `published_year`, `copies`  | index on year                         |
| `Loan`   | `book` → Book (PROTECT), `borrower` → User, `borrowed_at`, `due_at`, `returned_at` | unique open loan per (book, borrower) |

| Method            | URL                                                                      | Who    | Result                          |
| ----------------- | ------------------------------------------------------------------------ | ------ | ------------------------------- |
| GET               | `/api/books/` (`?author=`, `?published_year=`, `?search=`, `?ordering=`) | anyone | paginated list                  |
| POST/PATCH/DELETE | `/api/books/`, `/api/books/<id>/`                                        | staff  | 201 / 200 / 204                 |
| GET               | `/api/authors/`                                                          | anyone | with `book_count`               |
| GET/POST          | `/api/loans/`                                                            | member | own loans / borrow              |
| POST              | `/api/loans/<id>/return/`                                                | member | 200, or 409 if already returned |
| POST              | `/api/auth/token/`                                                       | anyone | `{"token": ...}`                |

## Harden

- Writes are staff-only; members only reach their own loans (scoped queryset, plus an object
  permission as a second layer).
- `ModelSerializer` copies `unique=True` into validators, so a duplicate ISBN is a 400, not a crash.
- The database enforces one open loan per member and book, whatever the code does.
- Token authentication for API clients; session authentication only for the browsable API.
