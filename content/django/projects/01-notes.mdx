## How this project works

Each milestone says what to build, gives hints if you get stuck, and then shows the solution: the
real files of a finished project whose test suite passes in CI. Build it yourself first, in your own
folder. When you're done with a milestone, run its checkpoint and tick it off; your progress is saved
in this browser.


## The brief (PRD)

A **product requirements document** answers: what problem, for whom, what exactly, and how we'll know
it's done. Writing it first stops you building the wrong thing. Here is the one for this project.

**Problem.** People jot quick notes in many places and can't find them later.

**Users.** One person, on their own computer (no accounts yet; the Auth starter adds them).

**User stories.**

- As a user I can **create** a note with a title and an optional body.
- I can **see all notes**, pinned ones first, then the most recently edited.
- I can **search** titles and bodies.
- I can **edit** and **pin** a note, and **delete** it.
- I see a short confirmation after every change.

**Acceptance criteria.**

- Titles are 3–120 characters after trimming spaces; a shorter title shows an error on the form.
- The list shows 10 notes per page.
- Delete only works with POST (a link or prefetch can't delete).
- Every form is CSRF-protected.
- `GET /health/` returns `{"status": "ok"}`.

**Out of scope.** Users and sharing, rich text, attachments, an API.

## Design

**Data model.** One table:

| Field                       | Type             | Rules                             |
| --------------------------- | ---------------- | --------------------------------- |
| `id`                        | big auto         | primary key                       |
| `title`                     | `CharField(120)` | required, 3+ chars after trimming |
| `body`                      | `TextField`      | optional (`blank=True`)           |
| `pinned`                    | `BooleanField`   | default `False`                   |
| `created_at` / `updated_at` | `DateTimeField`  | `auto_now_add` / `auto_now`       |

Default ordering: `-pinned`, `-updated_at`.

**URLs.**

| URL             | Name           | View                                 | Methods   |
| --------------- | -------------- | ------------------------------------ | --------- |
| `/`             | `notes:list`   | `note_list` (search `?q=`, `?page=`) | GET       |
| `/new/`         | `notes:create` | `note_create`                        | GET, POST |
| `/<pk>/edit/`   | `notes:edit`   | `note_edit`                          | GET, POST |
| `/<pk>/delete/` | `notes:delete` | `note_delete`                        | POST      |
| `/health/`      | `health`       | `health`                             | GET       |

## Harden

- `SECRET_KEY` and `DEBUG` come from the environment; the app refuses to start in production
  without a key:

<ProjectFile path="config/settings.py" />

- Delete is POST-only and every form has `{% csrf_token %}` (a test checks a POST without a token gets
  403).
- Templates escape note content, so a note titled `<script>` is harmless.
- `fields = ["title", "body", "pinned"]` in the form: nothing else can be set from a request.
