## Intuition: Russian dolls

To count the dolls in a Russian doll set, you open one doll, count it, and ask the same question of
the doll inside. You stop when a doll is solid, with nothing inside. That's the **base case**. Each
open doll waits until the inner count comes back, then adds one. Recursion works the same way. Each
call waits on the stack for the smaller call to answer.

## The precise rules

A correct recursive function needs:

1. **A base case** that answers without recursing, such as `n <= 1 → 1`.
2. **Progress:** every recursive call must move closer to the base case, such as `n - 1`.

$$
n! =
\begin{cases}
1 & n \le 1 \\
n \cdot (n-1)! & n > 1
\end{cases}
$$

Each active call holds a frame. CPython limits the depth (by default **1000**,
`sys.getrecursionlimit()`) and raises `RecursionError` past it. Python does **not** optimise tail
calls, so very deep recursion must become a loop.

## Worked example

```python title="recursion.py"
import sys
from functools import lru_cache


def factorial(n: int) -> int:
    if n <= 1:  # base case
        return 1
    return n * factorial(n - 1)  # progress: n gets smaller


def nested_sum(items: list) -> int:
    """Sum numbers in arbitrarily nested lists, a natural fit for recursion."""
    total = 0
    for x in items:
        total += nested_sum(x) if isinstance(x, list) else x
    return total


def forever(n: int) -> int:
    return forever(n - 1)  # no base case


print(factorial(5), nested_sum([1, [2, [3, 4]], 5]), sys.getrecursionlimit())

try:
    forever(5)
except RecursionError as err:
    print("RecursionError:", err)

calls = 0


def slow_fib(n: int) -> int:
    global calls
    calls += 1
    return n if n < 2 else slow_fib(n - 1) + slow_fib(n - 2)


@lru_cache(maxsize=None)
def fib(n: int) -> int:
    return n if n < 2 else fib(n - 1) + fib(n - 2)


slow_fib(20)
print(calls, fib(80))
print(fib.cache_info())
```

```text title="Output"
120 15 1000
RecursionError: maximum recursion depth exceeded
21891 23416728348467685
CacheInfo(hits=78, misses=81, maxsize=None, currsize=81)
```

What to notice:

- `nested_sum` handles any nesting depth with a few lines. Recursion shines when the **data
  itself is recursive** (nested lists, trees, folders).
- `forever` has no base case, so it runs until CPython stops it at the depth limit.
- The naive `slow_fib(20)` makes **21,891 calls**, because it recomputes the same values again
  and again. With `@lru_cache`, `fib(80)` computes each `n` once: 81 misses and 78 cache hits.

## Common mistakes

<Callout type="warning" title="Raising the recursion limit as a fix">
  `sys.setrecursionlimit(100_000)` can crash the interpreter with a real stack overflow. If your
  input can be deep (say, a linked list of 10,000 nodes), rewrite with a loop and an explicit stack.
</Callout>

- **A base case that's never reached.** `factorial(-3)` would recurse forever if the base case were
  `n == 1`. Use `n <= 1`, or validate the input.
- **Forgetting to `return` the recursive result.** Writing `factorial(n - 1)` without `return`
  makes the caller get `None`.
- **Mutable defaults in recursive helpers.** `def walk(node, seen=[])` shares `seen` across calls.
  Use `None` and create a new list (see lesson 10).

<KeyTakeaways>

- Recursion needs a **base case** and **progress** toward it.
- Every pending call holds a frame. The default depth limit is about 1000, and Python has no
  tail-call optimisation.
- Use `@lru_cache` when the same sub-problems repeat.
- Prefer a loop for long, linear processes. Prefer recursion for tree-shaped data.

</KeyTakeaways>
