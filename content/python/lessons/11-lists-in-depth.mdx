## Intuition: a row of numbered lockers

A list is a row of numbered lockers in one corridor, each holding a **reference** to an object. To
find locker 7 you walk straight to it (O(1)). Adding a locker at the end is easy if the corridor has
spare space. Squeezing one in at the **front** means every occupant moves one door to the right.

## The precise rules

| Operation                                   | Cost           | Why                     |
| ------------------------------------------- | -------------- | ----------------------- |
| `xs[i]`, `xs[i] = v`, `len(xs)`             | O(1)           | slots are contiguous    |
| `xs.append(v)`, `xs.pop()`                  | O(1) amortized | work at the end only    |
| `xs.insert(0, v)`, `xs.pop(0)`, `del xs[0]` | O(n)           | every later item shifts |
| `v in xs`, `xs.index(v)`, `xs.count(v)`     | O(n)           | must scan               |
| `xs.sort()`, `sorted(xs)`                   | O(n log n)     | Timsort                 |

- `xs.sort()` sorts **in place** and returns `None`. `sorted(iterable)` returns a **new** list and
  works on any iterable.
- `key=func` sorts by `func(item)`. Python calls `key` once per item.
- Sorting is **stable**: items with equal keys keep their original order.

## Worked example

```python title="lists.py"
nums = [5, 2, 9, 1]
ordered = sorted(nums)  # new list
print(ordered, nums)
result = nums.sort()  # in place
print(result, nums)

people = [("bo", 25), ("al", 30), ("cy", 25)]
print(sorted(people, key=lambda p: p[1]))  # stable: bo stays before cy
print(sorted(people, key=lambda p: (-p[1], p[0])))  # age desc, then name

print(sorted(["b", "A", "c"]), sorted(["b", "A", "c"], key=str.lower))

a = [1, 2, 3]
a.extend([4, 5])
a.insert(1, 9)
print(a, a.index(9))
print(a.pop(), a)
a.remove(9)
print(a)

try:
    [1, 2].index(7)
except ValueError as err:
    print("ValueError:", err)

print([0] * 3, 3 in [1, 2, 3], [1, 2, 3, 4][::-1])
```

```text title="Output"
[1, 2, 5, 9] [5, 2, 9, 1]
None [1, 2, 5, 9]
[('bo', 25), ('cy', 25), ('al', 30)]
[('al', 30), ('bo', 25), ('cy', 25)]
['A', 'b', 'c'] ['A', 'b', 'c']
[1, 9, 2, 3, 4, 5] 1
5 [1, 9, 2, 3, 4]
[1, 2, 3, 4]
ValueError: 7 is not in list
[0, 0, 0] True [4, 3, 2, 1]
```

What to notice:

- `nums.sort()` returned `None`. A classic bug is `nums = nums.sort()`, which leaves you with `None`.
- Uppercase letters sort before lowercase (`'A'` < `'b'` by code point). `key=str.lower` sorts
  case-insensitively.
- A tuple key sorts by the first field, then breaks ties with the next. Negating a number reverses
  just that field.
- `remove(v)` deletes the first matching **value**, and `pop(i)` removes by **index** and returns it.

## Variations

### Ways to build a list

```python title="build_lists.py"
print([3, 1, 2], list("abc"), list(range(2, 12, 3)))
print([n * n for n in range(6) if n % 2 == 0])          # comprehension with a filter
print("10,20,30".split(","), [int(x) for x in "10,20,30".split(",")])
print(list({"b": 1, "a": 2}), list((4, 5)), list())
print([[0] * 3 for _ in range(2)])                      # 2 independent rows
first, *middle, last = [1, 2, 3, 4, 5]                   # star-unpacking a list
print(first, middle, last)
```

```text title="Output"
[3, 1, 2] ['a', 'b', 'c'] [2, 5, 8, 11]
[0, 4, 16]
['10', '20', '30'] [10, 20, 30]
['b', 'a'] [4, 5] []
[[0, 0, 0], [0, 0, 0]]
1 [2, 3, 4] 5
```

`list(iterable)` turns anything iterable (string, dict keys, tuple, range) into a list. A
comprehension does the same while transforming and filtering.

### Slice assignment: replace, insert and delete ranges

```python title="slice_assign.py"
xs = [0, 1, 2, 3, 4, 5]
xs[1:3] = ["a", "b", "c"]      # replace 2 items with 3: the list grows
print(xs)
xs[1:1] = ["NEW"]               # an empty slice inserts
print(xs)
xs[-2:] = []                    # assigning [] deletes
print(xs)
del xs[::2]                     # delete every second item
print(xs)

ys = list(range(6))
ys[::2] = ["x", "y", "z"]       # extended slices need the SAME length
print(ys)
```

```text title="Output"
[0, 'a', 'b', 'c', 3, 4, 5]
[0, 'NEW', 'a', 'b', 'c', 3, 4, 5]
[0, 'NEW', 'a', 'b', 'c', 3]
['NEW', 'b', 3]
['x', 1, 'y', 3, 'z', 5]
```

A slice on the **left** of `=` names a region to replace with the contents of any iterable. Plain
slices may change the list's length; slices with a step must be replaced by exactly as many items.

### `append`, `extend`, `+` and `insert`

```python title="adding.py"
a = [1, 2]
a.append([3, 4])          # adds ONE item (the list itself)
print(a)

b = [1, 2]
b.extend([3, 4])          # adds each item of the iterable
b.extend("hi")            # a string is an iterable of characters
print(b)

c = [1, 2]
d = c + [3]               # a NEW list; c is unchanged
print(c, d)

e = [1, 2, 3]
e.insert(0, "start")      # O(n): shifts every item
e.insert(100, "end")      # an index past the end just appends
print(e)
```

```text title="Output"
[1, 2, [3, 4]]
[1, 2, 3, 4, 'h', 'i']
[1, 2] [1, 2, 3]
['start', 1, 2, 3, 'end']
```

`append(x)` always adds exactly one element, even if `x` is a list; `extend(it)` adds as many
elements as the iterable yields. `+` builds a new list, which is the choice when the original must
stay unchanged.

### Removing items

```python title="removing.py"
xs = ["a", "b", "c", "b", "d"]
print(xs.pop(), xs.pop(0), xs)        # by index, returns the item
xs.remove("b")                         # first matching value only
print(xs)
xs = [n for n in [3, 1, 3, 2, 3] if n != 3]   # remove ALL occurrences: rebuild
print(xs)
del xs[0]                              # by index, returns nothing
print(xs)
xs.clear()                             # empty the same list object
print(xs)
```

```text title="Output"
d a ['b', 'c', 'b']
['c', 'b']
[1, 2]
[2]
[]
```

Choose by what you know: the **position** (`pop(i)`, `del xs[i]`) or the **value**
(`remove(v)`, or a comprehension to drop every match).

### Searching sorted lists with `bisect`

```python title="bisect_demo.py"
import bisect

scores = [12, 25, 25, 31, 47, 58]
print(bisect.bisect_left(scores, 25), bisect.bisect_right(scores, 25))
print(bisect.bisect_left(scores, 30))           # where 30 would go
bisect.insort(scores, 30)                         # insert, keeping the list sorted
print(scores)


def grade(score, cutoffs=(60, 70, 80, 90), letters="FDCBA"):
    return letters[bisect.bisect(cutoffs, score)]


print([grade(s) for s in [55, 60, 75, 89, 90, 100]])
```

```text title="Output"
1 3
3
[12, 25, 25, 30, 31, 47, 58]
['F', 'D', 'C', 'B', 'A', 'A']
```

- `bisect` finds a position in a **sorted** list in O(log n), instead of scanning in O(n).
- `bisect_left` returns the first position where the value could go; `bisect_right` (alias
  `bisect`) returns the position after any equal values.
- The `grade` function turns a list of cut-offs into a lookup without an `if` chain.

### Sorting recipes

```python title="sorting_more.py"
from operator import itemgetter

rows = [
    {"name": "ada", "dept": "eng", "salary": 120},
    {"name": "bob", "dept": "ops", "salary": 90},
    {"name": "cy", "dept": "eng", "salary": 100},
    {"name": "dee", "dept": "ops", "salary": 110},
]
by_salary = sorted(rows, key=itemgetter("salary"), reverse=True)
print([r["name"] for r in by_salary])
by_dept_then_salary = sorted(rows, key=lambda r: (r["dept"], -r["salary"]))
print([(r["dept"], r["name"]) for r in by_dept_then_salary])

files = ["file10.txt", "file2.txt", "file1.txt"]
print(sorted(files), sorted(files, key=lambda f: int(f[4:-4])))   # natural order

xs = [3, 1, 2]
xs.reverse()                                    # in place, no sorting
print(xs, list(reversed(xs)))
```

```text title="Output"
['ada', 'dee', 'cy', 'bob']
[('eng', 'ada'), ('eng', 'cy'), ('ops', 'dee'), ('ops', 'bob')]
['file1.txt', 'file10.txt', 'file2.txt'] ['file1.txt', 'file2.txt', 'file10.txt']
[2, 1, 3] [3, 1, 2]
```

- `itemgetter("salary")` is a fast, readable `key` for dicts (and `itemgetter(1)` for tuples).
- A tuple key with a negated number sorts ascending on the first field and descending on the
  second.
- Plain string sorting puts `file10` before `file2`; extracting the number gives the "natural"
  order people expect.

### Lists of lists

```python title="grid.py"
grid = [
    [3, 8, 1],
    [9, 2, 7],
    [4, 6, 5],
]
print(grid[1][2], grid[-1][0])                       # row, then column
print([sum(row) for row in grid])                    # row sums
print([sum(col) for col in zip(*grid)])              # column sums
print([grid[i][i] for i in range(len(grid))])        # main diagonal
print([n for row in grid for n in row])              # flatten
for row in grid:
    print(" ".join(f"{n:2}" for n in row))
```

```text title="Output"
7 4
[12, 18, 15]
[16, 16, 13]
[3, 2, 5]
[3, 8, 1, 9, 2, 7, 4, 6, 5]
 3  8  1
 9  2  7
 4  6  5
```

`grid[r][c]` first picks the row list, then the item in it. `zip(*grid)` yields the columns, and
the double comprehension flattens: read it as nested loops, outer first.

### Classic list algorithms

```python title="list_algorithms.py"
def dedupe(items):
    seen, out = set(), []
    for x in items:
        if x not in seen:          # O(1) set lookup instead of scanning out
            seen.add(x)
            out.append(x)
    return out


def chunks(items, size):
    return [items[i:i + size] for i in range(0, len(items), size)]


def rotate(items, k):
    k %= len(items)
    return items[-k:] + items[:-k]


def window_sums(items, k):
    total = sum(items[:k])
    sums = [total]
    for i in range(k, len(items)):
        total += items[i] - items[i - k]      # slide: add the new item, drop the old
        sums.append(total)
    return sums


def merge_sorted(a, b):
    i = j = 0
    out = []
    while i < len(a) and j < len(b):
        if a[i] <= b[j]:
            out.append(a[i])
            i += 1
        else:
            out.append(b[j])
            j += 1
    return out + a[i:] + b[j:]


print(dedupe([3, 1, 3, 2, 1]), dict.fromkeys([3, 1, 3, 2, 1]).keys())
print(chunks(list(range(7)), 3), rotate([1, 2, 3, 4, 5], 2))
print(window_sums([1, 3, 2, 6, 4], 3), merge_sorted([1, 4, 9], [2, 3, 10]))
```

```text title="Output"
[3, 1, 2] dict_keys([3, 1, 2])
[[0, 1, 2], [3, 4, 5], [6]] [4, 5, 1, 2, 3]
[6, 11, 12] [1, 2, 3, 4, 9, 10]
```

- `dedupe` keeps the first occurrence of each item in order. `dict.fromkeys(items)` does the same
  using the fact that dicts keep insertion order.
- `window_sums` updates the running total in O(1) per step instead of re-summing each window: the
  **sliding window** pattern, O(n) instead of O(n·k).
- `merge_sorted` walks two sorted lists with two pointers, the merge step of merge sort.

## Putting it together: a gradebook

```python title="gradebook.py"
students = [
    ("ada", [92, 88, 95]),
    ("bob", [75, 64, 81]),
    ("cy", [88, 91, 85]),
    ("dee", [92, 88, 95]),
    ("eve", [58, 70, 66]),
]

averages = [(name, round(sum(s) / len(s), 1)) for name, s in students]
ranked = sorted(averages, key=lambda pair: (-pair[1], pair[0]))

print("rank name  avg")
rank = 0
previous = None
for position, (name, avg) in enumerate(ranked, start=1):
    if avg != previous:            # equal averages share a rank (1, 1, 3, ...)
        rank = position
    previous = avg
    print(f"{rank:>4} {name:5} {avg}")

per_test = [round(sum(col) / len(col), 1) for col in zip(*(s for _, s in students))]
print("test averages:", per_test)
print("top 2:", [name for name, _ in ranked[:2]])
print("below 70:", [name for name, avg in averages if avg < 70])
```

```text title="Output"
rank name  avg
   1 ada   91.7
   1 dee   91.7
   3 cy    88.0
   4 bob   73.3
   5 eve   64.7
test averages: [81.0, 80.2, 84.4]
top 2: ['ada', 'dee']
below 70: ['eve']
```

One list of `(name, scores)` pairs answers several questions: averages with a comprehension,
ranking with a tuple sort key (ties broken by name), "competition ranking" with a loop that
remembers the previous value, and per-test averages by transposing with `zip(*...)`.

## Common mistakes

<Callout type="warning" title="Using a list as a queue">
  `queue.pop(0)` is O(n). With a million items that's a million moves per call. Use
  `collections.deque` (lesson 16).
</Callout>

- **`if x in big_list` inside a loop** makes the loop O(n²). Convert to a `set` once if you test
  membership repeatedly.
- **Sorting mixed types.** `sorted([1, "a"])` raises `TypeError: '<' not supported between
instances of 'str' and 'int'`.
- **Copy surprises.** `b = a` aliases. Use `a.copy()` or `a[:]` (lesson 10).

## Practice

<Reveal
  kind="hint"
  label="Quick check: how do you sort words by length, longest first, ties alphabetically?"
>
  `sorted(words, key=lambda w: (-len(w), w))`. The negated length sorts long words first, and the
  word itself breaks ties alphabetically.
</Reveal>

<Reveal
  kind="hint"
  label="Quick check: what's the difference between `a.append([1, 2])` and `a.extend([1, 2])` on `a = [0]`?"
>
  `[0, [1, 2]]` versus `[0, 1, 2]`. `append` adds one element (the list); `extend` adds each element
  of the iterable.
</Reveal>

<Reveal kind="hint" label="Quick check: what does `xs = [1, 2, 3]; xs[1:2] = []` leave?">
  `[1, 3]`. Assigning an empty list to a slice deletes that range; it's the same as `del xs[1:2]`.
</Reveal>

<Reveal
  kind="hint"
  label="Quick check: how do you get the 3 largest numbers of a list without sorting everything?"
>
  `heapq.nlargest(3, nums)` runs in O(n log 3). `sorted(nums, reverse=True)[:3]` also works but
  sorts all n items (lesson 17 covers heaps).
</Reveal>

<KeyTakeaways>

- A list is a dynamic array: fast at the end and by index, slow at the front and for searches.
- `sort()` changes the list and returns `None`. `sorted()` returns a new list.
- Use `key=` (often a lambda or a tuple) instead of writing comparison logic.
- Sorting is stable, so multi-field sorts are easy.
- `append` adds one item, `extend` adds many, `+` makes a new list; slice assignment replaces,
  inserts or deletes ranges.
- On a **sorted** list, `bisect` finds positions in O(log n) and `insort` keeps it sorted.
- Patterns worth knowing by heart: dedupe in order, chunking, rotation, sliding window, two-pointer
  merge.

</KeyTakeaways>
